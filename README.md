## Kafka mentoring exercises

### Prerequisite

Run Apache Kafka in KRaft mode via Docker.
- Use a single-topic setup with 1 partition
- Configure this topic manually via Kafka CLI (e.g., kafka-topics.sh)

### Task 1: Kafka producer

- Develop a simple Kafka producer using Spring Boot
  - Create two classes:
    - Order: includes a unique ID (up to 100 unique values), timestamp, and a list of Products. (Note: unique ID limitation is required for follow-up tasks)
    - Product: includes at least id, name, and quantity.
  - Orders with a random number of Products (suggest: 1-5) are generated by a scheduled task.
  - Serialize each Order to JSON and publish it to the configured Kafka topic.
  - The Kafka message key must be the Order ID.

### Task 2: Kafka consumer
Develop a second Spring Boot application that consumes events from the Kafka topic created in Task 1.
- The application should:
  - Consume messages from the topic using a Kafka listener
  - Use the same Order and Product classes for deserialization.
  - Log the following information for each consumed message:
    - Topic name
    - Partition number
    - Order ID
    - (Optional) Product count 
  - JSON deserialization is sufficient, but feel free to test with XML as well for comparison.
  - No persistence or processing is needed at this stage — logging is sufficient to verify correct consumption.

### Task 2 follow-ups
Use these experiments to explore how Kafka handles partitioning, consumer groups, and offset behavior.

#### Consumer Group Behavior
- Start another instance of your Kafka consumer using the same group-id
  - Observe: If there is only 1 partition, what your Kafka Consumers do?
- Stop the active (reading) consumer
  - Observe: What happens with the other consumer
- Start both again
  - Now stop the non-reading one — observe what happens
- Change the group-id of one instance
  - Observe: What has changed in your consumer's behaviour?

#### Offset Reset Behavior
- Set auto.offset.reset to latest or earliest (and vice versa)
- What happens when:
  - You restart a previously stopped consumer (same group-id)
  - You start a new consumer with a new group-id

#### Partitioning and Scaling Out
- Create a new topic with 3 partitions
- Start
  - 2 consumers in the same group
  - 1 consumer in a different group
  - Observe: partition assignments, message consumptions and rebalancing
- Use the same Order ID as the Kafka message key
  - Observe: 
    - Partitions that messages are sent to
    - Ordering of messages

### Task 3 (Optional): Multi-Broker Kafka Cluster
This task introduces Kafka clustering with multiple brokers and explores how partition replication works across a distributed setup.
- Start a 3-broker Kafka cluster
- Create a topic with:
  - 3 partitions
  - Replication factor = 3
- Verify broker and partition distribution using Kafka CLI or Kafka UI
- Expected outcome:
  - Partitions are distributed across brokers
  - Each partition is replicated on another broker

### Task 4 (Optional): Broker Failure Observation
Observe how Kafka behaves when a broker goes offline in a multi-broker, replicated setup.
